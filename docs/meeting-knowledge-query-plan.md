# 会议历史问答开发计划

2026-11-19 · v1.0 · 待实施方案

本计划在现有持久化、任务队列、缓存及 GPU 调度基础上增加会议知识查询。新增结构和指标均为设计目标。配套六张架构图见 [图册](architecture/README.md)，包含可查看的 SVG 及可编辑的 Mermaid 源文件。

## 1. 两个问题需要怎样的查询能力

“上周的几次会议有哪些人参加？”需要确定会议发生时间、查全会议集合、按会议事件去重、关联可信参会人，再说明缺失名单。“去年今天的会议讨论了什么主题？”需要先查出对应日期的会议，再逐场读取议题及其原文依据。

向量检索适合寻找语义相近的片段。Top-K 结果不能代表时间范围内的全部会议，也无法证明一个没有发言的人缺席。两个例子首先需要可查询的时间、参会事实、完整会议集合和证据，再由模型组织答案。

| 问题 | 优先查询方法 | 回答依据 |
| --- | --- | --- |
| 上周各场会议有哪些人、各人参加几次 | 时间解析 + 参数化 SQL 关联与去重聚合 | 会议事件、参会状态、名单来源及身份缺口 |
| 去年今天各场会议的主题 | SQL 列出当天全部会议 + 议题及转写证据 | 每场会议的主题与引用，缺项时补查正文 |
| 某场会议怎样讨论某问题 | SQL 定位会议 + 词法/向量混合召回 + rerank | 该场转写段及音频时间轴 |
| 上月哪些会议提到成本过高 | SQL 时间过滤 + 主题标签/候选全量判别 + 语义检索 | 区分有证据的命中、已扫描范围和未覆盖会议 |
| 某项目的决定怎样演变、谁负责跟进 | 时间事实 + 项目/议题/决策/行动项关系查询 | 有效时间上的关系及原文证据 |
| “所有人”“共几次”“从未参加” | 完整集合与覆盖检查后确定性计算 | 缺数据或有限召回时返回部分答案及缺口 |

**推荐路径**是自然语言转受验证的 QueryPlan，调用 SQL、检索及关系工具。Baseline 使用 SQL 模板。优化版扩展组合计划和时态关系查询。NL2SQL 按复杂统计问题的收益逐类启用；知识图谱先用 PG 关系表表达，Neo4j 按实测收益决定。

## 2. 当前实现与缺口

核对依据为本地 `persistence/schema.py`、`persistence/repository.py`、`server.py`、`agent/vector_store.py`、`agent/prompts.py`。

| 当前实现 | 需要补充 |
| --- | --- |
| PG 保存来源、任务、转写段、分类、报告、面试题和阶段产物 | 独立会议事件。一场会议多份录音或多次分析不能按任务数计数 |
| 来源含创建、修改、发布日期，任务有提交和完成时间 | 会议发生时间、时区、日期精度和可信来源，不能用上传时间替代 |

| 全局检索无上下文时允许用通识回答 | 私人会议问题应明确未命中、构建未完成或检索故障 |

## 3. 会议、时间和参与人的语义

### 3.1 会议事件与媒体分开

新增 `meeting_sessions` 表示一场真实会议，`meeting_recordings` 关联媒体版本及分析版本。同一会议的分段录音、重复上传和重跑分析可以引用同一事件。

字节哈希能确定相同内容，不能证明不同哈希属于不同会议。标题相同也不足以自动合并。自动归并优先采用可信平台事件 ID，其他情况呈候选供确认。统计以 session ID 去重，并选择已确认的来源和有效分析版本。“会议”默认筛选 meeting 类别，面试、视频和其他录音可在页面显式切换，答案显示本次口径。

### 3.2 时间和精度

会议保存 `event_start_at`、`event_end_at`、`event_local_date`、`event_timezone`、`time_precision`、`time_status`。时间候选保存原值、来源、证据、解析版本、置信和确认状态。

建议优先级为人工确认、可信平台/日历事件元数据、录音中明确陈述的日期、文件名日期、文件元数据。冲突需展示候选来源。只有月日但缺年份的文件名不能直接补成上传年份。文件修改、上传和报告生成时间只表达各自语义。

| 表达 | 产品规则 | 以 2026-11-19、Asia/Shanghai 为锚点 |
| --- | --- | --- |
| 上周 | 上一自然周，周一零点到本周一零点，左闭右开 | 2026-11-09 00:00 ≤ 时间 < 2026-11-16 00:00 |
| 最近七天 | 从查询时刻向前七天 | 与上周独立解释 |
| 去年今天 | 用户时区中上一公历年同月同日 | 2025-11-19 00:00 ≤ 时间 < 2025-11-20 00:00 |
| 某天的会议 | 按会议发生日期筛选 | 不用报告生成日代替 |
| 跨午夜会议 | 默认按开始日归属；问“期间举行过”用区间重叠 | 页面提供口径切换 |
| 闰日的去年今天 | 对应日期不存在时澄清 2 月 28 日或 3 月 1 日 | 澄清前不执行精确日查询 |

请求固定当前时刻和用户时区，业务时间模块解析一次再转换 UTC。只知道日期时保留 date 精度，不伪造准确开始时间。DST 地区按日历计算边界，不固定每个自然日为 24 小时。多轮对话保留查询锚点，跨日继续查询时展示并确认范围。低可信候选单独列为可能匹配，不混入精确统计。

### 3.3 参会人、发言人和被提及者

- 平台实际出席记录、可信签到或用户确认支持“确认参会”。邀请名单只能支持“受邀”。自我介绍、说话人发言和其他原文支持不同强度的关系，均保留来源。
- Speaker-01 只在单份转写中有意义。先存转写内的 speaker 映射，有证据或人工确认后再绑定人物。没有说话不等于缺席，被提到名字也不等于参会。
- 人物按工作区、组织、别名和上下文归一。同名多人时呈候选，无法确认则留未知。允许撤销误合并，保留合并、拆分和确认历史。
- 跨会议去重按 person ID，未知 speaker 只在会议内计数。页面区分每场名单、跨场唯一人数、累计人次。名单不全时回答可确认发言者并说明覆盖。
- Baseline 使用文本和名单映射；声纹识别在另有需求和数据授权后单独评估。

## 4. 增量数据库与证据模型

沿用 `meeting_agent` 数据库和 `meeting` schema，通过新迁移增加下列对象。所有记录直接或经外键归属工作区。

| 对象 | 主要字段及责任 |
| --- | --- |
| meeting_sessions | id、workspace_id、title、category、发生时间/本地日期、时区、精度、确认状态、current_revision；统计主实体 |
| meeting_recordings | session_id、media_version_id、analysis_id、is_primary、confirmation_status、valid_from/to；多录音与分析版本关联 |
| meeting_time_candidates | 原始时间、解析值、精度、时区、source_kind、confidence、evidence_id、parser_version、review_state |
| people / person_aliases | 标准人物、工作区别名、组织、有效期和确认状态，裸姓名不作为全局唯一键 |
| speaker_links | transcript_id、speaker_label、person_id、映射状态、证据和版本 |
| meeting_participants | session_id、person_id 或未知 speaker_link、presence_status、role、confidence、有效期和事实版本 |
| meeting_topics | session_id、title、summary、topic_entity_id、source_analysis_id、coverage_state、revision |
| evidence_spans | transcript_id、segment_id、字符范围、audio_start/end_ms、text_hash、来源版本；名单可引用受控元数据快照 |
| facts / fact_evidence | 受约束的事实登记、类型、主体和客体，事实与证据的支持/反驳关系、抽取版本和确认者 |
| knowledge_builds | source_revision、extractor_version、model、state、已完成/总单元数、错误及水位 |
| query_runs / query_evidence | 身份作用域、绝对时间范围、计划版本、候选/匹配/覆盖数、执行状态、最终引用与时延 |
| conversation_sessions / conversation_turns | 按用户和工作区持久化会话、上一轮事件集合、范围及上下文版本 |
| knowledge_entities / knowledge_relations | 优化版的项目、议题、决策、行动项和有类型关系，带有效时间、置信及证据 |

人物和会议沿用专表作为主数据，图谱关联这些 ID。事实表及各专表要设计数据库外键和一致性约束，避免只保存不可校验的字符串引用。抽取断言与人工确认独立记录，查询视图选择当前有效版本。

索引先覆盖工作区与事件日期/开始时间、会议与参会人/状态、人物别名、转写与证据段、关系的起点/类型/终点及有效时间。未知时间、软删除和有效版本考虑部分索引。每次引用读取和缓存复用都重新核对权限。

## 5. Baseline 版本

交付目标是稳定回答两个指定问题，并说明回答完整到什么程度。

### 5.1 离线构建

现有分析成功后同事务写知识构建 outbox，通过 RabbitMQ 增量处理。先复用 result_json、已有名单和转写段；有缺项时补做时间、人物、议题抽取。结构校验、证据定位、身份及完整性检查通过后入库，页面提供日期与人物确认。

抽取缓存按转写哈希、工作区、规则/模型/提示词版本和人工纠正版本入键。新增时间候选、人物、议题三个构建阶段，复用已有队列和 GPU 调度。历史回填复用现有 ASR 与报告，仅计算缺失事实。

### 5.2 在线执行

1. 捕获真实用户、工作区、当前时刻和时区。
2. 模型提取受验证 QueryPlan，包含 intent、对象类型、时间表达、人物/项目候选、分组、排序、完整性要求及证据类型。作用域由服务注入。
3. 时间模块给出绝对区间和精度，同名人物与关键日期歧义进入澄清。
4. 受控工具调用参数化 SQL。工具包括 list_meetings、list_attendees、get_meeting_topics、aggregate_attendance、get_meeting_evidence。
5. 聚合由 SQL/程序完成，摘要按每场会议有证据的议题组织。长结果逐批处理后做覆盖检查，不能用分页样本算总数。
6. 返回名单/主题、绝对日期、原文/音频引用、缺失字段、扫描会议数及回答状态。

| 用户问题 | 实际查询计划 | 输出约束 |
| --- | --- | --- |
| 上周的几次会议有哪些人参加？ | 自然周 + meeting 类型 → SQL 全量 session → 有效参会关系与证据 | 按场显示名单、可信状态及未知身份；集合和数量由库计算 |
| 去年今天的会议讨论了什么主题？ | 去年同日区间 → SQL 全量事件 → 该集合内全部有效议题和证据 | 逐场列主题及出处，缺项显示待补充；无匹配明确说明范围 |

Baseline 使用自然语言转有限查询计划，开发者维护 SQL 模板即可完成上述问题。会议—人物—议题的简单关系由 PG 关联表实现。先验证时间和实体质量，再引入更复杂的生成与图查询。

## 6. 优化后的目标版本

### 6.1 查询编排与混合检索

常见问题保留模板快路径。扩展经过模式校验的 DAG 查询计划，支持 SQL 的会议集合约束向量检索、关系结果约束 SQL、以及先定位某个决策再查看前后事件。硬约束先执行，检索在可访问候选集合内开展，随后词法/向量融合及 rerank。

已有 Chroma 可用于对照；目标优先评估 PG + pgvector 与词法检索共库，使来源 ID、事实版本和权限更容易对齐。迁移前以相同语料和问题影子对比。中文项目名、短词和人名需独立评估分词及召回，默认英文全文分词不能直接作为中文方案。pg_trgm 适用于相似匹配；向量近似扫描在过滤条件下的召回不足需用精确检索基准校验。[pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html)、[pgvector](https://github.com/pgvector/pgvector)。

“全部”“多少”类问题必须扫描完整匹配事件集或完整事实表。语义条件下的总数要先对候选全量判别，持久化判别结果后聚合。Top-K 搜索结果只能声称搜索命中，页面显示扫描范围和截断状态。长任务转异步，允许用户查询进度。

### 6.2 受约束 NL2SQL

模板之外的多维统计，例如“上季度各项目参会次数最多的前三个人，并比较前一季度”，可在优化阶段引入 NL2SQL。

| 环节 | 设计 |
| --- | --- |
| 语义层 | 仅暴露审核过的指标、视图、连接路径、去重和版本口径，维护字段及枚举含义 |
| 生成 | 优先生成结构化关系代数或查询 AST 再编译；SQL 字符串仅在受控实验通路接收 |
| 静态校验 | 单条查询、白名单视图/函数/连接，拒绝写入、多语句、系统对象、文件/网络函数；不能仅判断 SELECT 前缀 |
| 身份隔离 | 真实身份由服务注入，专用只读角色受安全视图/RLS 约束；非 owner，无 BYPASSRLS；连接池按事务重设并清理上下文 |
| 执行预算 | 事务只读、statement timeout、行数/字节/复杂度限制，必要时 EXPLAIN 预估后执行 |
| 校验回退 | 核对时间、实体、去重、指标和完整性，有限修正后仍失败则回模板或澄清 |
| 上线闸门 | 和模板及标准结果集合对比，按意图逐类开放，通过越权与资源消耗测试 |

只读事务仍可能执行昂贵或敏感函数，需要数据库权限、函数白名单和资源预算一起控制。RLS 的 owner/超级用户绕过行为纳入验收。[PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)。

### 6.3 事件知识图谱

目标图谱实体包括 Meeting、Person、Organization、Project、Topic、Decision、ActionItem，关系包括参与、讨论、关联项目、作出决定、替代旧决定、分配给和跟进。用于回答的边附证据、有效时间、抽取置信及确认状态。

初期使用 PG 表和固定一跳/有限多跳工具。决策有效时间与知识入库时间分开保存，以区分“当时的决定”和“后来更正后的认识”；组织归属与别名同样保留有效期。

Neo4j 作为可选读投影。拟定引入门槛是有价值的 2–3 跳问题占评测集至少 20%，且 PG 关系查询已成为延迟或维护瓶颈。用相同问题比对正确率、P95、内存和一致性成本后决定。引入时通过 outbox 投影实体和边，PG 保持事实依据，图数据库保存同步水位。权限撤销和删除先在主库撤销回答资格，投影落后时回退 PG。

GraphRAG 用于扩展有关系的证据，实体消歧和缺失事实仍需独立处理。上述门槛和 PG 主库、Neo4j 投影是项目设计选择。[Neo4j GraphRAG](https://neo4j.com/labs/genai-ecosystem/graphrag/)。

### 6.4 页面与对话

历史问答页展示本次日期范围、扫描会议数、已解析身份、未知名单、知识构建状态及引用。回答状态包括完整、部分、需澄清、无匹配、数据不可用。引用可打开原文段、音频位置及版本。

人物页可确认别名和 Speaker 绑定；会议页可纠正发生日期、类型和名单；项目页显示主题和决策时间线。多轮中的“那几场”“其中张三几次”引用上一轮事件集，每次执行重新验证权限。

答案按逐条 claim、工具事实和证据 ID 校验。名单和数字由程序检查，语义归纳做引用支持率抽查。检索到的提示注入作为不可信原文，工具权限和查询范围由系统限定。

## 7. 完整性、版本和缓存

| 情况 | 行为 |
| --- | --- |
| 日期未知/矛盾 | 从确定集合排除，列为可能匹配并提供确认入口 |
| 仅发言人可知 | 输出可观察发言人，说明完整名单缺失 |
| 无命中、索引关闭、数据库不可用 | 分别反馈无匹配、检索能力不可用和服务故障，避免编造私人会议 |
| 重跑或多份录音 | 按事件和当前确认版本去重，可切历史版本 |
| 新导入、纠错、删除或撤销权限 | 提升知识/权限版本，答案缓存立即失效，异步投影追平 |
| 投影滞后 | 用主库事实回答；需要语义索引时显示覆盖不足或等更新 |
| 结果过多 | 完成确定性聚合后分页，主题摘要分批处理并显示覆盖数 |
| 相互矛盾的证据 | 保留支持/反驳和出处，确认后形成新有效版本 |

查询缓存键包含访问作用域与权限版本、规范 QueryPlan、绝对时间范围、会话指代的事件集合、知识版本、索引水位、模型及回答模板。TTL 之外需要主动失效。缓存命中仍检查引用是否有效。

已有录音、ASR 与报告作为回填输入。新增构建按源版本幂等派发，完成的部分可断点复用。后台事实抽取/向量索引与在线问答分别限额。SQL 查询不申请 GPU，本地抽取和重排复用共享 GPU profile；避免历史回填占满单张 3060 Ti。

| K0 审计与标准集 | 盘点日期、身份、主题和重复会议覆盖；确定规则；修正无证据回答策略 | 至少 80 个合成/授权标准问题，覆盖指定问题、缺年份、跨日、时区、同名、未知身份、重复分析和越权 |

| K2 Baseline | 时间模块、QueryPlan、模板 SQL、名单聚合、带引用主题摘要 | 固定事实集的时间边界/数量/去重结果 100% 正确，端到端目标 ≥90%，权限样本全部通过 |
| K3 混合检索 | 过滤 + 词法/向量融合 + rerank，多轮持久化，缓存和索引水位 | 与原 Top-K 路径对比 Recall@20、引用及完整性；纠错/删除生效；截断不能当完整统计 |

| K5 发布观测 | 灰度、覆盖看板、反馈、重建恢复和回滚 | 逐类开放，24 小时混合读写观察，能切回模板通路并显示未支持范围 |

### 分层指标

- 时间固定规则集覆盖自然周、滚动天数、跨年、闰日、DST、精度和来源冲突，目标 100% 正确；无法确定的表达正确澄清。
- 人物抽取和消歧分别算 precision/recall，确认名单 precision 目标 ≥98%。未知身份可以为空，概率分不能替代人工确认状态。
- SQL 以结果集合和聚合值验证，避免只比 SQL 字符串。测试跨工作区、撤权、连接池上下文残留和投影过期。
- 引用覆盖率和人工支持率目标均 ≥95%，明确统计数字与工具输出一致率 100%；数据缺失时正确给出部分/未知状态的比例 ≥95%。
- 初始性能预算为 1 万场事件、100 万转写段，模板查询 P95 ≤2 秒，含模型问答 P95 ≤15 秒。云端响应和长问题超预算时转异步或分页，依据实测确定发布上限。
- Baseline 和优化版使用同一冻结时间、数据划分和标准答案，报告正确率、覆盖率、拒答率、延迟、成本和误合并。新增技术需产生可量化收益。

上述数字均为拟定验收目标。真实数据覆盖、性能和质量需实施后测量。
