## 前端实现原理

### SSE (Server-Sent Events) 读取

```javascript
// 1. 发起请求
const response = await fetch(`${API}/api/chat/${task.task_id}/stream`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: msg }),
});

// 2. 创建助手消息占位
const assistantMsg = { role: 'assistant', content: '' };
chatMessages.push(assistantMsg);

// 3. 读取 SSE 流
const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop() || '';

  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const data = JSON.parse(line.slice(6));
      
      if (data.type === 'token') {
        // 逐 token 追加到消息内容
        assistantMsg.content += data.data.content;
        scrollChatToBottom();
      } else if (data.type === 'done') {
        // 完成，使用最终内容
        assistantMsg.content = data.data.reply || assistantMsg.content;
      }
    }
  }
}
```

### 关键点

1. **ReadableStream API**: 使用 `response.body.getReader()` 读取 SSE 流
2. **逐 token 渲染**: 每收到一个 token 事件，立即追加到 `assistantMsg.content`
3. **实时滚动**: 每次更新后调用 `scrollChatToBottom()` 保持可见
4. **降级策略**: SSE 失败时自动降级到传统 POST 请求

## 后端实现原理

### SSE 端点结构

```python
@app.post("/api/chat/{task_id}/stream")
async def chat_stream(task_id: str, req: ChatRequest):
    # 1. 验证任务状态
    if task_id not in tasks:
        raise HTTPException(404, "任务不存在")
    
    # 2. 构建上下文（转写文本 + 分析报告 + 对话历史 + RAG）
    messages = ctx_mgr.build_chat_context(...)
    
    # 3. 定义事件生成器
    async def event_generator():
        # 发送开始事件
        yield f"data: {json.dumps({'type': 'start'})}\n\n"
        
        # 流式调用 LLM
        full_content = ""
        async for token in llm.chat_messages_stream(messages, ...):
            full_content += token
            yield f"data: {json.dumps({'type': 'token', 'data': {'content': token}})}\n\n"
        
        # 发送完成事件
        yield f"data: {json.dumps({'type': 'done', 'data': {'reply': full_content}})}\n\n"
    
    # 4. 返回 StreamingResponse
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",  # 禁用 Nginx 缓冲
        }
    )
```

### 关键点

1. **async generator**: 使用 `async for` 逐 token 生成事件
2. **SSE 格式**: `data: {json}\n\n` 格式，前端通过 `data: ` 前缀识别
3. **StreamingResponse**: FastAPI 的流式响应类
4. **禁用缓冲**: `X-Accel-Buffering: no` 确保事件立即发送

## 常见问题

### Q1: 为什么我之前没看到流式输出？

**A**: 因为任务追问对话（`/api/chat/{task_id}`）之前确实没有实现流式输出。现在已经补上，所有对话场景都支持流式输出了。

### Q2: 流式输出有什么好处？

**A**:
1. **降低感知等待时间**: 用户无需等待完整生成，实时看到内容生成过程
2. **更好的用户体验**: 视觉上更流畅，减少"卡住"的感觉
3. **实时反馈**: 即使 LLM 生成较慢，用户也能看到进度

### Q3: 如果流式输出失败怎么办？

**A**: 所有流式端点都有降级策略：
- SSE 连接失败 → 自动降级到传统 POST 请求
- 用户无感知，只是看不到逐字渲染效果

### Q4: 流式输出会消耗更多资源吗？

**A**: 不会。流式输出只是改变了数据传输方式（逐 token vs 一次性），总的数据量和计算量是相同的。
