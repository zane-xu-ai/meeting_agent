> Phase 2 记忆系统第二个里程碑
> 前置: M4 短期记忆 ✅ (三层分级压缩)
> 目标: 跨任务记忆 — "上次关于XX项目的会议说了什么"、"对比最近三次会议"

---

## 1. 架构总览

```
                    ┌──────────────────────────────────────────────┐
                    │           写入路径 (Indexing)                 │
                    │                                              │
  分析完成 ─▶ format_output ─▶ parent_child_chunk() ─▶ embed() ─▶ ChromaDB
                    │                                              │
                    └──────────────────────────────────────────────┘

                    ┌──────────────────────────────────────────────┐
                    │           读取路径 (Retrieval + Rerank)       │
                    │                                              │
  用户追问 ─▶ embed(query) ─▶ ChromaDB 粗检索 top-20 ─▶ Rerank top-5
                    │                                              │
                    ▼                                              │
  chat 接口 ◀── 注入检索结果 (含父块上下文) ────────────────────────┘
```

**核心特性**:
- Embedding: `qwen3.7-text-embedding-flash` (DashScope)
- Rerank: `qwen3.7-text-rerank` (精排，提升检索准确度)
- 分块: 父子块策略 (Parent-Child)，子块检索 + 父块注入上下文

## 2. 父子块分块策略

### 2.1 设计理念

```
┌─ 父块 (Parent) ─────────────────────────────────────┐
│  完整上下文，注入到 LLM prompt                       │
│  例: H2 段落全文 (~200-500 字符)                     │
│                                                      │
│  ┌─ 子块 (Child) ──────────────┐  ┌─ 子块 ────────┐ │
│  │ 用于向量检索 + Embedding     │  │               │ │
│  │ ~100-300 字符               │  │ ~100-300 字符 │ │
│  └─────────────────────────────┘  └───────────────┘ │
└──────────────────────────────────────────────────────┘
```

- **子块**: 用于 Embedding + 向量检索 (精确匹配)
- **父块**: 检索命中后，将父块注入 LLM 上下文 (提供完整语境)
- 解决 "检索到片段但缺少上下文" 的问题

### 2.2 Summary 分块规则

基于实际数据分析 (2 个样本文件):

```
会议纪要结构:
  ## 全文摘要       (197 字符, 无 H3)
  ## 章节速览       (454 字符, 含 5 个 H3, 每个 H3 约 33-93 字符)
  ## 关键决策       (248 字符, 无 H3)
  ## 待办事项       (337 字符, 无 H3)
  ## 关键词         (41 字符, 无 H3)
```

**分块方案**:

| 场景 | 父块 | 子块 |
|------|------|------|
| H2 无 H3 (如 `## 全文摘要`) | H2 标题 + 内容 (~200 字符) | 同父块 (父子相同) |
| H2 有 H3 (如 `## 章节速览`) | H2 标题 + 所有 H3 内容 (~450 字符) | H2 标题 + 单个 H3 (~120-190 字符) |

**为什么子块要包含 H2 标题?**
- 单独 H3 如 "3. 智能体架构与核心功能设计" 只有 33 字符，语义不完整
- 加上 H2 前缀后: "章节速览 - 3. 智能体架构与核心功能设计: 详细拆解七大子智能体职责..." (~120 字符)
- 子块包含父级标题，检索时语义更完整，Embedding 质量更高

**示例**:

```
父块 P1: "全文摘要 - 本次会议围绕伊利VIC权益系统及AI分析项目展开...(197字)"
  └ 子块 C1: (同父块，无 H3)

父块 P2: "章节速览 - (共5节)\n1. 团队介绍...(33字)\n2. 项目背景...(58字)\n3. 智能体架构...(58字)\n4. 技术路线...(69字)\n5. 里程碑...(62字)"
  └ 子块 C2a: "章节速览 - 1. 团队介绍与会议准备: 参会人员互相认识...(33字)"
  └ 子块 C2b: "章节速览 - 2. 项目背景与业务目标: 汇报VIC权益系统...(58字)"
  └ 子块 C2c: "章节速览 - 3. 智能体架构与核心功能设计: 详细拆解...(58字)"
  └ 子块 C2d: ...
  └ 子块 C2e: ...

父块 P3: "关键决策 - 1. 本期项目范围明确为...(248字)"
  └ 子块 C3: (同父块，无 H3)

父块 P4: "待办事项 - | 任务 | 负责人 | 截止时间 |...(337字)"
  └ 子块 C4: (同父块，无 H3)
```

### 2.3 ASR 分块规则

基于实际数据分析 (88 行样本):

```
ASR 文件格式: [00:00 -> 00:08] Speaker-00: 朋友们，我现在手边的...
每行: 42-114 字符 (平均 70 字符)
```

**分块方案**:

| 层级 | 内容 | 大小 |
|------|------|------|
| 子块 | ASR 单行 (含时间戳 + 说话人 + 文本) | 42-114 字符 |
| 父块 | ~500 字 (多个连续子块) | 360-550 字符, 6-9 行 |

**实际分组效果** (小米评测视频, 88 行):

```
父块 1:  行 1-8,   510 字符 (开场介绍)
父块 2:  行 9-17,  548 字符 (外观设计)
父块 3:  行 18-24, 527 字符 (屏幕升级)
父块 4:  行 25-31, 525 字符 (防窥屏)
父块 5:  行 32-39, 530 字符 (外放音质)
父块 6:  行 40-47, 514 字符 (电池续航)
...
父块 12: 行 83-88, 360 字符 (结尾)
```

**评估**: 分组均匀 (360-550 字符)，每个父块覆盖一个自然话题段落，策略合理 ✅

### 3.2 Rerank 客户端 — `agent/reranker.py` (新建)

```python
class RerankerClient:
    """DashScope Rerank 客户端"""

    def __init__(
        self,
        model: str = "qwen3.7-text-rerank",
        api_key: str | None = None,
        base_url: str | None = None,
    ):
        # 复用 settings.dashscope_api_key

    async def rerank(
        self,
        query: str,
        documents: list[str],
        top_n: int = 5,
    ) -> list[RerankResult]:
        """
        对候选文档重排序

        Args:
            query: 查询文本
            documents: 候选文档列表
            top_n: 返回前 N 个

        Returns:
            按相关性排序的结果列表
        """

@dataclass
class RerankResult:
    index: int         # 原始索引
    content: str       # 文档内容
    score: float       # 重排分数
```

**Rerank 流程**:
```
用户查询 → Embedding → ChromaDB 粗检索 top-20 → Rerank 精排 → top-5 注入上下文
```

**为什么需要 Rerank?**
- Embedding 检索是语义相似度 (余弦距离)，可能召回不相关的结果
- Rerank 模型是交叉编码器 (Cross-Encoder)，对 query-document 对做精确打分
- 两阶段: 粗检索 (高召回) + 精排 (高精度) = 最佳检索质量

### 3.4 向量存储 — `agent/vector_store.py` (新建)

```python
class VectorStore:
    """ChromaDB 向量存储 (父子块架构)"""

    def __init__(
        self,
        persist_dir: str = "data/vector_store",
        child_collection: str = "meeting_child",   # 子块集合 (用于检索)
        parent_collection: str = "meeting_parent", # 父块集合 (用于上下文)
    ):
        # 两个 collection:
        # - child: 存储子块 embedding，用于向量检索
        # - parent: 存储父块内容，用于检索后取回完整上下文

    async def add_chunks(self, parent_chunks: list[ParentChunk],
                         child_embeddings: list[list[float]]) -> int:
        """写入父子块: 子块 → child collection, 父块 → parent collection"""

    async def search_with_rerank(
        self,
        query: str,
        query_embedding: list[float],
        reranker: RerankerClient,
        coarse_top_k: int = 20,   # 粗检索数量
        final_top_k: int = 5,     # 精排后数量
        filters: dict | None = None,
    ) -> list[SearchResult]:
        """
        三阶段检索:
        1. 子块向量粗检索 (top-20)
        2. Rerank 精排 (top-5)
        3. 取回对应父块作为上下文
        """

    async def get_parent(self, parent_id: str) -> ParentChunk | None:
        """根据 parent_id 取回父块"""

@dataclass
class SearchResult:
    child_content: str     # 命中的子块
    parent_content: str    # 对应的父块 (注入 LLM 的上下文)
    score: float           # rerank 分数
    task_id: str
    source_type: str       # "summary" | "asr"
    source_file: str
    section: str           # 所属章节
```

**双 Collection 设计**:
```
child_collection:
  - 存储: 子块内容 + embedding + parent_id (元数据)
  - 用途: 向量检索 (高召回)

parent_collection:
  - 存储: 父块内容 + task_id + metadata (不需要 embedding)
  - 用途: 检索命中子块后，通过 parent_id 取回父块
```

**依赖**:
- `requirements.txt` — 新增 `chromadb>=0.5.0`

## 7. 面试话术

| 考点 | 关键表述 |
|------|---------|
| RAG | "两阶段检索: Embedding 粗检索 top-20 + Rerank 精排 top-5，检索质量显著提升" |
| Parent-Child Chunking | "子块用于精确检索，父块提供完整上下文注入 LLM，解决片段检索缺少语境的问题" |
| Embedding | "qwen3.7-text-embedding-flash，DashScope OpenAI 兼容接口" |
| Rerank | "qwen3.7-text-rerank 交叉编码器，对 query-document 对精确打分" |
| 分块策略 | "Summary 按 Markdown H2/H3 语义切分；ASR 按 ~500 字滑动窗口，子块为单行" |
| 双 Collection | "child collection 存子块+embedding 用于检索，parent collection 存父块用于上下文取回" |

## 8. 风险与降级

| 风险 | 降级方案 |
|------|---------|
| Rerank API 不可用 | 跳过精排，直接用 Embedding 粗检索结果 |
| ChromaDB 安装失败 | 降级为内存字典 (task_id → list[Chunk]) |
| Embedding API 失败 | 跳过索引，日志记录；检索返回空 |
| 检索结果不相关 | 调低 coarse_top_k；增加 rerank score 阈值 |
