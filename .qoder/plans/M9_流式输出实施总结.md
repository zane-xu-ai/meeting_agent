# M9 流式输出实施总结

> **实施日期**: 2026-10-06  
> **状态**: ✅ 完成  
> **目标**: LLM 分析结果流式输出到前端，用户无需等待完整生成

---

## 实施概览

### 核心架构

```
LLM 流式调用 → asyncio.Queue → SSE 端点 → 前端 EventSource
```

**技术选型**:
- **传输协议**: SSE (Server-Sent Events) — 单向推送，比 WebSocket 更简单
- **流式范围**: 主要针对 LLM 分析阶段（会议总结/通用总结）
- **降级方案**: 保留原有轮询机制，SSE 失败自动降级

## 实施细节

### M9.1: LLMClient 流式输出支持

**文件**: `agent/llm_client.py`

**新增方法**:
1. `chat_stream()` — 流式单轮对话
2. `chat_messages_stream()` — 流式多轮对话
3. `_chat_stream_with_model()` — 底层流式调用实现
4. `_chat_messages_stream_with_model()` — 底层流式多轮调用

**实现要点**:
- 使用 `httpx.AsyncClient.stream()` 读取 SSE 响应
- 解析 `data: {...}` 格式的 SSE 事件
- 提取 `choices[0].delta.content` 作为增量 token
- 支持模型列表自动 fallback（与原有逻辑一致）

**代码示例**:
```python
async for token in llm.chat_stream(prompt):
    yield token  # 逐 token 返回
```

---

### M9.2: agent_loop 节点流式输出

**文件**: `agent/graph.py`

**新增组件**:
1. `_stream_queue_registry` — 流式事件队列注册表（task_id → asyncio.Queue）
2. `register_stream_queue()` — 注册流式队列
3. `unregister_stream_queue()` — 注销流式队列
4. `_push_stream_event()` — 推送事件到队列

**事件类型**:
- `start` — 开始流式输出 `{"rec_type": "meeting"|"general"|...}`
- `token` — 增量 token `{"content": "..."}`
- `done` — 完成 `{"output_text": "完整内容"}`
- `error` — 错误 `{"message": "..."}`
- `heartbeat` — 心跳（每 15 秒）

**修改节点**:
- `_fallback_analyze()` — 会议分析和通用分析支持流式输出
  - 检查是否注册流式队列
  - 有队列：使用 `chat_stream()` 逐 token 推送
  - 无队列：使用传统 `chat_json()` 非流式调用
  - 缓存命中时也流式输出（逐字符推送）

**代码示例**:
```python
if has_stream_queue:
    await _push_stream_event(task_id, "start", {"rec_type": rec_type})
    async for token in llm.chat_stream(prompt):
        await _push_stream_event(task_id, "token", {"content": token})
    await _push_stream_event(task_id, "done", {"output_text": output_text})
```

### M9.3: server.py SSE 端点

**文件**: `server.py`

**新增端点**: `/api/stream/{task_id}` (GET)

**实现逻辑**:
1. 检查任务是否存在
2. 如果任务已完成：
   - 直接返回完整结果（分块模拟流式）
3. 如果任务正在进行：
   - 创建 asyncio.Queue
   - 注册到 graph 模块
   - 从队列读取事件并发送 SSE
   - 15 秒超时发送心跳保持连接
   - 任务完成后自动结束流

**SSE 格式**:
```
data: {"type": "start", "data": {"rec_type": "meeting"}}

data: {"type": "token", "data": {"content": "## "}}

data: {"type": "token", "data": {"content": "会议"}}

data: {"type": "done", "data": {"output_text": "完整内容..."}}
```

**HTTP 头**:
```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no  # 禁用 Nginx 缓冲
```

### M9.4: 前端流式渲染

**文件**: `frontend/index.html`

**修改函数**: `fetchResult()`

**实现逻辑**:
1. 创建 EventSource 连接 `/api/stream/{task_id}`
2. 监听 `onmessage` 事件：
   - `start` — 清空当前内容
   - `token` — 追加到 `resultMd`
   - `done` — 关闭连接，更新元数据
   - `error` — 显示错误信息
   - `heartbeat` — 忽略（保持连接）
3. 监听 `onerror` 事件：
   - 降级到传统轮询 `fetchResultFallback()`

**降级方案**:
```javascript
eventSource.onerror = (e) => {
  eventSource.close();
  if (!fullContent) {
    fetchResultFallback();  // 降级到轮询
  }
};
```

## 关键设计决策

### 1. SSE vs WebSocket

**选择**: SSE

**理由**:
- 只需要服务端到客户端的单向推送
- 基于 HTTP，更简单、更兼容
- 自动重连机制（浏览器原生支持）
- 不需要额外的协议升级

### 2. 流式范围

**选择**: 仅 LLM 分析阶段

**理由**:
- ASR 阶段是外部 API 调用，无法流式
- 预处理/分类阶段耗时短，无需流式
- LLM 生成阶段耗时最长（10-60 秒），流式收益最大

### 3. 降级策略

**选择**: 保留轮询 + 自动降级

**理由**:
- 兼容性：旧浏览器可能不支持 SSE
- 稳定性：SSE 连接失败时自动降级
- 灵活性：用户可以选择关闭流式输出

### 4. 事件队列设计

**选择**: asyncio.Queue per task

**理由**:
- 与现有进度回调注册表模式一致
- 避免在 LangGraph state 中存储不可序列化的对象
- 支持多个 SSE 客户端同时连接（虽然前端只用一个）

## 性能优化

### 1. 分块发送

对于已完成的任务，分块发送内容（50 字符/块），模拟流式效果，避免一次性加载大文件。

### 2. 心跳机制

每 15 秒发送心跳事件，防止代理服务器（如 Nginx）因超时关闭连接。

### 3. 禁用缓冲

设置 `X-Accel-Buffering: no` 头，禁用 Nginx 缓冲，确保事件立即发送到客户端。

## 已知限制

### 1. 面试分析未流式化

**原因**: 面试分析分为 `question.md` 和 `analyze.md` 两个文件，逻辑较复杂。

**未来优化**: 可以分别流式输出两个文件，或合并为一个流。

### 2. Agent Loop 未流式化

**原因**: Agent Loop 使用 Function Calling，LLM 返回的是完整 JSON，无法流式。

**未来优化**: 可以在 Tool 执行阶段推送进度事件，但不是真正的 token 流式。

### 3. 缓存命中时逐字符推送

**原因**: 缓存内容是完整字符串，为了流式效果逐字符推送，可能不够平滑。

**优化方案**: 可以按行或按段落推送，而不是逐字符。
